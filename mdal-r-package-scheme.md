# R Package for MDAL: Feasibility Assessment and Design Scheme

## Executive Summary

MDAL (Mesh Data Abstraction Library) has a clean C API with ~70 functions, making it highly suitable for R bindings. No existing R package wraps MDAL. The recommended approach is **cpp11 with S7 classes** for the user-facing layer.

## Prior Work

**rmdal0** (https://github.com/mdsumner/rmdal0) - A minimal proof-of-concept from the MDAL 0.3.3 era (~2019). Used native C++ with autoconf configure script. Successfully linked to system MDAL and called `MDAL_Status()`. This provides a useful reference for:
- Configure script patterns for finding MDAL
- Basic package structure
- The native C approach (which we'll modernize with cpp11)

The MDAL API has matured substantially since then (now 1.3.2) with additions like 1D meshes, 3D volumes, mesh editing, and many new drivers.

## Technology Choice: cpp11 vs Rcpp vs Native R API

### Recommendation: **cpp11**

| Criterion | Rcpp | cpp11 | Native R |
|-----------|------|-------|----------|
| CRAN acceptance | Good | **Excellent** | Excellent |
| Header-only | No (links to Rcpp) | **Yes** | N/A |
| Compile times | Slower | **Faster** | N/A |
| Modern C++ | C++11+ | **C++11+ (cleaner)** | C only |
| Vendor bundling | Complex | **Simple** | N/A |
| External pointer handling | Good | **Good** | Manual |
| Learning curve for you | Known | Similar to Rcpp | Higher |
| Future maintenance | Active | **Active, simpler deps** | Stable |

**Rationale:**
1. cpp11 is now the preferred choice for new CRAN packages (used by tidyverse)
2. Header-only = simpler distribution, no Rcpp DLL dependency
3. Clean external pointer semantics with automatic release via cpp11's `cpp11::external_pointer<T>`
4. Better alignment with R's memory model
5. Rcpp Modules are powerful but add complexity; cpp11 + S7 is cleaner

### Against Rcpp Modules
While Rcpp Modules can auto-generate R6-like classes from C++, they:
- Add significant compilation complexity
- Make debugging harder
- Tie you to Rcpp's class system rather than R's emerging standard (S7)

## Layered API Design

### Layer 1: cpp11 Raw Bindings (internal)

Low-level wrappers that mirror the C API almost 1:1. These are internal (`@keywords internal`).

```cpp
// src/mdal_mesh.cpp
#include <cpp11.hpp>
#include <mdal.h>

using namespace cpp11;

// Custom deleter for MDAL_MeshH
inline void mdal_mesh_release(MDAL_MeshH mesh) {
  if (mesh) MDAL_CloseMesh(mesh);
}

[[cpp11::register]]
sexp mdal_load_mesh_(std::string uri) {
  MDAL_MeshH mesh = MDAL_LoadMesh(uri.c_str());
  if (!mesh) {
    MDAL_Status status = MDAL_LastStatus();
    stop("Failed to load mesh: status %d", (int)status);
  }
  // Return as external pointer with release callback
  return external_pointer<void, mdal_mesh_release>(mesh);
}

[[cpp11::register]]
int mdal_mesh_vertex_count_(sexp mesh_xptr) {
  MDAL_MeshH mesh = (MDAL_MeshH)external_pointer<void>(mesh_xptr).get();
  return MDAL_M_vertexCount(mesh);
}

[[cpp11::register]]
doubles mdal_mesh_vertices_(sexp mesh_xptr, int start, int count) {
  MDAL_MeshH mesh = (MDAL_MeshH)external_pointer<void>(mesh_xptr).get();
  MDAL_MeshVertexIteratorH it = MDAL_M_vertexIterator(mesh);
  
  writable::doubles coords(count * 3);
  int read = MDAL_VI_next(it, count, REAL(coords));
  MDAL_VI_close(it);
  
  if (read < count) {
    coords = writable::doubles(coords.begin(), coords.begin() + read * 3);
  }
  return coords;
}

[[cpp11::register]]
std::string mdal_mesh_projection_(sexp mesh_xptr) {
  MDAL_MeshH mesh = (MDAL_MeshH)external_pointer<void>(mesh_xptr).get();
  const char* proj = MDAL_M_projection(mesh);
  return proj ? std::string(proj) : "";
}
```

### Layer 2: S7 Classes (exported)

User-facing S7 classes that wrap the external pointers with nice semantics.

```r
# R/mdal-mesh.R
library(S7)

#' MDAL Mesh
#' @export
MdalMesh <- new_class("MdalMesh",
  properties = list(
    ptr = new_property(class_any, 
      getter = function(self) self@.ptr,
      setter = function(self, value) {
        self@.ptr <- value
        self
      }
    ),
    uri = new_property(class_character),
    .ptr = new_property(class_any)  # internal storage
  ),
  validator = function(self) {
    if (is.null(self@.ptr)) return("Mesh pointer is NULL")
    NULL
  }
)

#' Load a mesh file
#' @param uri Path or URI to mesh file (can include driver hint)
#' @export
mdal_load <- function(uri) {
  ptr <- mdal_load_mesh_(uri)
  MdalMesh(uri = uri, .ptr = ptr)
}

# S7 generics and methods
method(print, MdalMesh) <- function(x, ...) {
  cat("<MdalMesh>\n")
  cat("  URI:", x@uri, "\n")
  cat("  Vertices:", mdal_mesh_vertex_count_(x@.ptr), "\n")
  cat("  Faces:", mdal_mesh_face_count_(x@.ptr), "\n")
  cat("  Edges:", mdal_mesh_edge_count_(x@.ptr), "\n")
  cat("  Dataset groups:", mdal_mesh_dataset_group_count_(x@.ptr), "\n")
  proj <- mdal_mesh_projection_(x@.ptr)
  if (nzchar(proj)) cat("
  CRS:", proj, "\n")
  invisible(x)
}

#' Get mesh vertices as matrix
#' @param mesh MdalMesh object
#' @return Nx3 matrix of vertex coordinates (x, y, z)
#' @export
method(vertices, MdalMesh) <- function(x) {
  n <- mdal_mesh_vertex_count_(x@.ptr)
  coords <- mdal_mesh_vertices_(x@.ptr, 0L, n)
  matrix(coords, ncol = 3, byrow = TRUE, 
         dimnames = list(NULL, c("x", "y", "z")))
}
```

## Critical Implementation Details

### 1. Handle Lifetime Management

cpp11's `external_pointer` handles this elegantly:

```cpp
// The release function is called when R garbage collects
template<typename T>
using mdal_ptr = cpp11::external_pointer<T, mdal_mesh_release>;
```

### 2. Iterator Pattern

MDAL uses iterators for efficiency (especially with lazy-loaded formats). Expose both:
- Low-level: `mdal_vertex_iterator_create()`, `mdal_vertex_iterator_next()`, `mdal_vertex_iterator_close()`
- High-level: Just call `vertices(mesh)` which handles everything

```r
# For advanced users who need chunked reading
mdal_iter_vertices <- function(mesh, chunk_size = 10000) {
  # Returns a function that yields chunks
  function() {
    # ... uses iterator internally
  }
}
```

MDAL supports 3D stacked meshes. The R interface should handle:
- Vertical level counts per face
- Volume indices
- 3D scalar/vector data

## Build System Considerations

### Option A: Link to System MDAL
```
# configure / configure.win
# Find MDAL via pkg-config or cmake
PKG_CPPFLAGS=$(pkg-config --cflags mdal)
PKG_LIBS=$(pkg-config --libs mdal)
```

**Pros:** Simpler, uses system library  
**Cons:** Requires MDAL installed, version mismatches possible

### Option B: Vendor MDAL Source (Recommended for CRAN)
Include MDAL source in `src/vendor/` and build statically.

**Pros:** Reproducible builds, no external dependency  
**Cons:** Larger package, must update manually, needs HDF5/NetCDF/GDAL optionally

### Recommendation
Start with **system MDAL** via conda-forge during development, then consider vendoring for CRAN submission. Given MDAL's dependency on GDAL/HDF5/NetCDF, system linkage is probably more practical long-term (similar to how sf links to system GDAL).

## Integration Details

There is a fidelity hierarchy from MDAL to rgl mesh to Simple Features. 

MDAL (vertices + faces + edges + volumes + datasets)
  ↓ loses: temporal datasets, volume data, mixed topology
rgl mesh3d (vertices + face indices)
  ↓ loses: true 3D, face index structure, edge semantics  
wk/sf (closed rings, polygon semantics)
  ↓ triangles become "polygons", topology is flattened
  
  
### wk Integration

wk is the natural foundation for R spatial - it's the geometry interchange format that sf, geos, s2 all understand.

```r
#' @export
as_wk.MdalMesh <- function(x, type = c("polygon", "face", "vertex", "edge"), ...) {
  type <- match.arg(type)
  
  switch(type,
    polygon = ,
    face = {
      # Each face becomes a polygon
      verts <- vertices(x)
      face_list <- faces(x)
      wk::wk_polygon(
        lapply(face_list, function(idx) {
          # Close the ring
          verts[c(idx, idx[1]), 1:2, drop = FALSE]
        })
      )
    },
    vertex = {
      verts <- vertices(x)
      wk::xy(verts[,1], verts[,2], verts[,3])
    },
    edge = {
      # 1D mesh edges as linestrings
      edges <- edges(x)
      verts <- vertices(x)
      wk::wk_linestring(
        lapply(seq_len(nrow(edges)), function(i) {
          verts[c(edges[i,1], edges[i,2]), 1:2, drop = FALSE]
        })
      )
    }
  )
}
```

### rgl mesh3d Integration

Start with **wireframe (lines)** - avoids triangulation complexity entirely and works for any face topology. Also natural fit for MDAL's 1D mesh support (edges are the primary geometry).

```r
#' @export
as_mesh3d.MdalMesh <- function(x, type = c("wire", "solid"), 
                                dataset = NULL, time = NULL, ...) {
 
  if (!requireNamespace("rgl", quietly = TRUE)) {
    stop("Package 'rgl' required. Install with install.packages('rgl')")
  }
  
  type <- match.arg(type)
  verts <- vertices(x)  # Nx3
  
  if (type == "wire") {
    # Extract all edges (face boundaries + 1D edges if present)
    # Each face [v1, v2, v3, v4] gives edges: v1-v2, v2-v3, v3-v4, v4-v1
    edges <- face_edges(x)  # Returns 2-column matrix of vertex indices
    
    # rgl::segment3d wants interleaved start/end points
    # Or use mesh3d with edges parameter (added in rgl 0.100.50)
    rgl::segment3d(
      x = verts[c(t(edges)), 1],
      y = verts[c(t(edges)), 2],
      z = verts[c(t(edges)), 3],
      ...
    )
  } else {
    # Solid requires triangulation - Phase 2
    # For now, only support pure triangle meshes
    face_list <- faces(x)
    sizes <- lengths(face_list)
    

    if (!all(sizes == 3)) {
      stop("Solid mesh3d currently requires all triangular faces. ",
           "Use type='wire' for mixed meshes, or triangulate first.")
    }
    
    tris <- do.call(cbind, face_list)
    
    colors <- NULL
    if (!is.null(dataset)) {
      data <- mdal_get_data(x, dataset, time)
      colors <- data_to_colors(data)
    }
    
    rgl::tmesh3d(
      vertices = t(verts),
      indices = tris,
      material = list(color = colors),
      ...
    )
  }
}

#' Extract face boundary edges
#' @keywords internal
face_edges <- function(mesh) {
  faces <- faces(mesh)
  edges <- vector("list", length(faces))
  
  for (i in seq_along(faces)) {
    f <- faces[[i]]
    n <- length(f)
    # Each consecutive pair + closing edge
    edges[[i]] <- cbind(f, c(f[-1], f[1]))
  }
  
  do.call(rbind, edges)
}
```

**Phasing:**
- Phase 1: `type = "wire"` - works immediately for any mesh
- Phase 2: `type = "solid"` with triangle-only restriction
- Phase 3: Add triangulation for n-gons (fan or ear-clipping)

### sf Integration  

sf just consumes wk directly - dead simple:

```r
#' @export
as_sf.MdalMesh <- function(x, dataset = NULL, time = NULL, ...) {
  if (!requireNamespace("sf", quietly = TRUE)) {
    stop("Package 'sf' required. Install with install.packages('sf')")
  }
  
  geom <- as_wk(x, type = "polygon")
  sfc <- sf::st_as_sfc(geom)
  sf::st_crs(sfc) <- mdal_crs(x)
  
  if (!is.null(dataset)) {
    data <- mdal_get_data(x, dataset, time)
    sf::st_sf(value = data, geometry = sfc)
  } else {
    sf::st_sf(geometry = sfc)
  }
}
```

**Design principle:** 
- **wk as core dependency** - it's lightweight (~no compiled code of its own) and is the interchange foundation. Having `as_wk()` always available means users can immediately pipe into sf, geos, s2, or anything else in that ecosystem.
- **sf, rgl in Suggests** - heavier dependencies, optional for users who need them
- **terra at arm's length** - users who need terra can go `as_wk() |> sf::st_as_sf() |> terra::vect()`. No need to add direct terra support initially.

```r
# Always works (wk is imported)
wk_mesh <- as_wk(mesh)

# Works if sf installed
sf_mesh <- sf::st_as_sf(wk_mesh)

# terra users can chain
terra_mesh <- terra::vect(sf::st_as_sf(as_wk(mesh)))
```

The `as_sf()` and `as_mesh3d()` convenience methods check for their packages:

```r
as_sf.MdalMesh <- function(x, ...) {
  if (!requireNamespace("sf", quietly = TRUE)) {
    stop("Package 'sf' required for as_sf(). Install with install.packages('sf')")
  }
  sf::st_as_sf(as_wk(x, ...))
}
```

## Summary Recommendations

1. **Use cpp11** - cleaner than Rcpp, no modules complexity, good external pointer support
2. **Use S7** for user-facing classes - future-proof, works well with cpp11
3. **Three-layer architecture** - raw bindings → S7 classes → convenience functions
4. **wk as core dependency** - lightweight, provides interop to sf/geos/s2 ecosystem
5. **sf, rgl in Suggests** - optional heavyweight dependencies
6. **Link to system MDAL** initially (via conda-forge), leverage rmdal0's configure pattern
7. **Start minimal** - core read functionality first, then expand
8. **Package name:** `rmdal` (builds on your prior rmdal0 work)
